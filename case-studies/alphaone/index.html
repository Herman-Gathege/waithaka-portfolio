01

Overview

AlphaOne is a full-stack SaaS platform for property managers, built collaboratively through a shared Git repository with peer code reviews across the stack. The front end is React with Vite; the back end is FastAPI with PostgreSQL; the whole stack runs through Docker Compose, with Redis in the mix alongside it.

The product covers the full letting cycle — organizations, properties, units, tenants, leases, billing, payments and finance analytics — and uses the WhatsApp Cloud API to handle tenant notifications, payment reconciliation and automated messaging workflows. It is live at alphaone.africa.

02

The challenge

Rental management software has to hold several things true at once, and every one of them reaches the screen:

  • Many organizations on one platform, with records that must stay strictly separated.
  • Different people needing different levels of access — what one role can see or change is not what another should.
  • Money flows running through the product: billing, payments, reconciliation and finance reporting.
  • Tenants who do not live in email — notifications and reminders have to arrive where they actually read them.
  • Dashboards used on an office laptop and on a phone at a property, which makes responsive behaviour a functional requirement rather than a nicety.

None of that is a purely visual problem: each screen depends on authorization, data integrity and third-party integrations behaving predictably.

03

My contribution

  • Designed responsive dashboards for organizations, properties, units, tenants, leases, billing, payments and finance analytics.
  • Implemented JWT authentication, ProtectedRoute components and role-based access control.
  • Worked on security hardening: rate limiting, PII encryption and HMAC-SHA256 blind indexes.
  • Integrated the WhatsApp Cloud API for tenant notifications, payment reconciliation and automated messaging workflows.
  • Developed collaboratively via a shared Git repository with peer code reviews across the stack.

AlphaOne is a team product. The contributions above are the ones documented in my CV; a fuller breakdown of who did what is available on request.

04

Approach

  • Front end: a React and Vite application built from components that consume RESTful endpoints for lists, detail views, billing and finance analytics.
  • Access control: JWT-based authentication with ProtectedRoute components, so unauthenticated users cannot reach application surfaces and role-based access control decides what each signed-in user can see and do.
  • Multi-tenant structure: dashboards scoped to an organization, with properties, units, tenants and leases hanging off that structure consistently.
  • Security in the model: rate limiting on the API, PII encrypted at rest, and HMAC-SHA256 blind indexes so records can be looked up without exposing raw values.
  • Messaging and reconciliation: WhatsApp Cloud API workflows for tenant notifications and payment reconciliation, so reminders and confirmations reach people in the channel they use.
  • Environments: Docker Compose runs the stack consistently for development and testing, with PostgreSQL storing data and Redis supporting the application alongside it.

08

Key takeaways

  • In a multi-tenant product, authorization is a product decision, not a middleware checkbox — it shapes navigation, empty states and what a dashboard is even allowed to show.
  • Third-party messaging integrations have their own delivery behaviour, and designing notifications means designing around that rather than assuming they arrive.
  • Encryption and blind indexes have to be designed with the data model; retrofitting them later is far more expensive than deciding early.
  • Peer reviews across the whole stack surfaced front-end assumptions early, while they were still cheap to change.
